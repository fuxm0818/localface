# LocalFace · 本地多人物人脸识别

[![打包桌面版](https://github.com/fuxm0818/localface/actions/workflows/build.yml/badge.svg)](https://github.com/fuxm0818/localface/actions/workflows/build.yml)

打开一个网页，用电脑摄像头认出画面里的人：已登记的人会画框并显示名字和相似度，没登记的人显示「未知」。
另有一个管理后台，可以用照片、摄像头或视频给每个人建立「人脸档案」。

所有计算都在你自己的电脑上完成，照片、视频和摄像头画面不会上传到任何服务器。

> 这个工具**没有用 YOLO**，用的是 InsightFace 的人脸检测 + ArcFace 人脸特征比对。

**最短路径**：`git clone` 本仓库 → 项目目录执行 `npm install && npm start`（模型会自动下载，约 170 MB）→ 用 Chrome 打开 http://localhost:5273 ；
第一次使用先去 http://localhost:5273/admin 添加人物和照片。详细步骤见第 3 节。

想要**双击即用、不开终端**的桌面版，见第 16 节（Tauri 壳 + 打包成 macOS `.app`）。

## 1. 它能做什么，不能做什么

**能做**

- 摄像头实时识别多个人：画面里每张脸都会画框；已登记的人显示名字和相似度，未登记的人显示「未知 NN%」
- 连续多帧投票：最近 12 帧里至少一半达标才稳定显示名字，避免闪一下误报
- 人物库管理：新增、改名、删除人物；每个人可以有几十到几百张人脸样本
- 四种录入方式：上传照片、选择整个文件夹、摄像头单张/连拍、从视频里按时间抽帧
- 样本管理：查看每张样本的对齐缩略图，单独删除录错的样本
- 全局阈值：在识别页或后台调整，写入数据库；识别页 15 秒内自动读取最新值
- 命令行批量导入：适合一次导入几百张照片，运行中的服务会自动加载，不用重启
- **距离提醒**：给指定人物开启后，靠屏幕太近会全屏弹出倒计时炸弹警告（两侧红边 + C4 炸药块 + 点名警告），退远自动拆除；可从菜单栏托盘直接开关
- **图片标注**：上传一张图片，自动标出里面每个人是谁（绿框=已登记，黄框=陌生人）
- **桌面版**：Tauri 打包成 macOS .app，启动后常驻菜单栏，不占窗口
- 从第一版自动迁移：第一版的 53 张「儿子」特征会自动导入新数据库

**不能做**

- 不录像、不截图、不做监控、不发通知
- 不做陌生人身份识别：未登记的人只会显示「未知」，不会去网上匹配是谁
- 没有活体检测：拿一张照片对着摄像头也可能被认出来，**不要用于门禁、考勤、支付等安全场景**
- 没有登录和权限：管理后台谁打开谁就能改。服务只监听本机 `127.0.0.1`，不要把端口暴露到局域网或公网
- 对很远、很糊、严重侧脸、口罩、逆光的画面不可靠（见第 10 节）
- 双胞胎、长相极像的兄弟姐妹可能混淆，这是所有人脸模型的通病

## 2. 你需要准备什么

| 项目 | 要求 | 说明 |
|---|---|---|
| 电脑 | macOS（已在 Apple 芯片上验证） | 代码本身跨平台，Windows / Linux 理论可用，但没测过 |
| Node.js | **22.13 或更高**（推荐 24 LTS） | 用的是 Node 自带的 SQLite（`node:sqlite`），不需要另外安装数据库 |
| 浏览器 | Chrome 或 Edge（推荐）；Safari 新版本理论可用但没测 | 必须用 `http://localhost` 打开，不能直接双击 `index.html` |
| 磁盘 | 约 480 MB | 依赖 293 MB + 模型 169 MB；人脸数据每张约 15 KB |
| 摄像头 | 笔记本自带或 USB 摄像头 | 第一次使用系统会问是否允许访问，点「允许」；桌面版误点拒绝后，页面里会给出「打开系统设置」按钮 |
| 网络 | 只在 `npm install` 时需要 | 装好之后完全离线可跑 |
| Python | 不需要 | 所有推理都在 Node 里跑 |
| GPU | 不需要 | CPU 即可，单张脸单帧约 110～160 ms |

**Node.js 怎么装**

- 打开 https://nodejs.org ，下载 **LTS** 版本（目前是 Node 24）的安装包，一路下一步；
- 或者用 Homebrew：`brew install node@24`；
- 装完在终端执行 `node -v`，应显示 `v22.13.0` 或更高。低于 22.13 会在启动时报找不到 `node:sqlite`。

**不需要安装的东西**

- 不需要 MySQL / PostgreSQL / SQLite 客户端：数据库是 Node 自带的，数据就是一个文件 `data/app.db`；
- 不需要 Python、CUDA、显卡驱动；
- 不需要手动下载人脸模型：模型不随 git 提交（体积大且有许可限制），`npm install` 和首次 `npm start` 会自动从网上下载到 `models/`（约 170 MB，国内网络优先走 hf-mirror.com 镜像）。见第 3.1 节和第 12 节。

## 3. 第一次使用

### 3.1 安装依赖

```bash
cd ~/Qoder/yolo
npm install
```

直接依赖只有两个：

- `onnxruntime-node`：本地推理引擎，体积较大（约 290 MB），装的时候耐心等；
- `jpeg-js`：读写 JPEG。

`npm install` 完成时会**自动下载人脸模型**到 `models/`（约 170 MB；国内网络默认走 hf-mirror.com 镜像，失败会自动换 huggingface.co）。如果当时网络不通，可以稍后手动补：

```bash
npm run setup
```

其实不手动补也没关系——`npm start` 启动时发现模型缺失会再自动下载一次。装好之后启动完全离线可跑。

`npm install` 只需要执行一次。以后启动不用再装。

### 3.2 启动服务

```bash
npm start
```

看到这几行说明启动成功（首次启动如果模型还没下载完，会先自动下载约 170 MB，之后加载模型约 3～8 秒）：

```
模型就绪：insightface buffalo_l w600k_r50
人物库就绪：0 人 / 0 张人脸 → data/app.db
识别服务已启动： http://localhost:5273
管理后台： http://localhost:5273/admin
摄像头画面只在本机 127.0.0.1 处理，不会上传。
```

如果你是**从第一版升级**，并且 `data/` 还没有数据，启动时会多两行：

```
已迁移 v1 模板：53 张人脸 → 人物「儿子」
正在后台生成 53 张旧样本的缩略图（不影响识别）…
```

这时人物库里已经有「儿子」和 53 张样本，可以直接跳到 3.4 开摄像头。
缩略图会在后台慢慢生成，期间识别不受影响。

### 3.3 先登记人物（全新安装）

1. 用 Chrome 打开 **http://localhost:5273/admin**
2. 点左上角「＋ 新增」，填名字（比如「儿子」），保存
3. 在右侧选择一种方式录入：
   - **上传照片**：一次选多张，或点「选择整个文件夹」；
   - **摄像头录入**：点「开启」，然后「录入当前画面」或「连拍 8 张」；
   - **视频抽帧**：选一段视频，抽 8 / 12 / 20 帧，逐帧录入。
4. 下方「人脸样本」出现缩略图就说明录入成功。建议每个人至少 **30 张**，覆盖不同角度、表情、光线。

录入规则（不满足会跳过，并在日志里写明原因）：

- 画面里只能有一个「主角」人脸，多人合影会跳过；
- 人脸要够大：照片/视频帧里脸宽至少 90 像素；
- 和已有样本几乎一样的（相似度 ≥ 0.97）会去重；
- 上传照片支持 jpg / png / webp；命令行导入只支持 jpg / jpeg。

### 3.4 打开识别页

1. 用 Chrome 打开 **http://localhost:5273**
2. 点「开启摄像头」，浏览器弹权限请求时点「允许」
3. 让对方站在摄像头前 **0.5～1.5 米**，正对镜头、正面光
4. 画面里出现彩色框 + 名字 + 相似度，就说明认出来了
5. 用完点「停止」；服务进程在终端按 `Ctrl+C` 结束

> 摄像头打不开？见第 12 节排查。

## 4. 管理后台

地址：http://localhost:5273/admin

### 4.1 人物

| 操作 | 说明 |
|---|---|
| ＋ 新增 | 建一个人物，名字必填、最多 30 字，名字不能重复 |
| 点击人物行 | 右侧显示这个人的样本、录入工具和缩略图 |
| 编辑 | 改名字和备注 |
| 删除人物 | 会删除这个人的全部特征和缩略图，**不可恢复**，删除前会二次确认 |

人物越多，识别时每个人都要比一遍，但 512 维向量的比对很快，几十个人对帧率影响很小。
真正影响帧率的是画面里的**人脸数量**：每张脸都要单独提一次特征。

### 4.2 四种录入方式

**上传照片**

- 可多选 jpg / png / webp，也可以直接拖进虚线框；
- 浏览器先在本地把照片缩到最长边 1280，再以原始像素发给本机服务；
- 服务检测人脸、检查质量、提取特征，只把 512 维特征和 112×112 的对齐缩略图存进数据库；
- **原始照片不会被复制或保存**，还在你原来的文件夹里。

**选择整个文件夹**

- 适合一次导入几十上百张；支持浏览器能解码的常见图片格式（jpg / png / webp 等，HEIC 通常不行）；
- 逐张显示成功或跳过原因，不会因为一张失败就中断。

**摄像头录入**

- 「开启」后可以「录入当前画面」，也可以「连拍 8 张」（间隔约 350 ms）；
- 连拍时稍微变换角度、表情，能快速补充样本；
- 画面里只留一个人，别人入镜会被拒绝；
- 只保存对齐后的人脸缩略图和特征，不保存整张摄像头画面。

**视频抽帧**

- 选一段本地视频，在浏览器里按时间均匀取 8 / 12 / 20 帧；
- 每帧单独检测、提特征、入库，某些帧没人脸、脸太小、多人同框会单独跳过，不影响其他帧；
- 视频只在浏览器里解码，**不上传、不保存**；
- 视频能否解码取决于浏览器。Chrome 对 H.264 MP4 支持最好；HEVC/H.265、部分 MOV 可能打不开；
- 抽帧需要逐帧跳转解码，12 帧通常要十几秒，进度条会显示进度。

### 4.3 人脸样本

- 每张样本显示 112×112 的对齐缩略图、来源、录入时间、脸宽；
- 点右上角「×」可以删除单张样本（录错人、太糊时用）；
- 第一版迁移过来的样本没有脸宽和缩略图元数据，会显示「旧样本」；缩略图生成后会正常显示；
- 缩略图是真正的图片（只是很小），不是特征向量。请把 `data/` 当私人数据保管。

建议：

- 每个人至少 30 张，最好 100 张以上；
- 覆盖不同光线（白天/晚上/开灯）、角度（正脸/轻微侧脸）、表情、戴不戴眼镜；
- 不要放别人照片、多人合影、严重模糊或遮挡的照片；
- 小孩长相变化快，建议每半年到一年补充一次新照片。

### 4.4 识别设置

- 阈值范围 0.30～0.65，默认 **0.45**；
- 阈值是全局设置，存在 SQLite 里，识别页和管理后台共享；
- 调高更严格（少认错，更容易认不出），调低更宽松（少漏认，更容易认错）；
- 修改后立即生效；识别页 15 秒内自动读取，切回标签页时也会立即刷新；
- 后台自己不会轮询：如果阈值是在识别页改的，刷新后台即可看到最新值。

### 4.5 操作日志

页面右侧记录本次打开后台后的操作结果：成功、跳过原因、失败原因。
刷新页面后日志清空，不影响数据库里的数据。

## 5. 识别页

地址：http://localhost:5273

| 控件 | 作用 |
|---|---|
| 开启摄像头 / 停止 | 开关摄像头和识别循环 |
| 摄像头下拉框 | 有多个摄像头（外接摄像头、虚拟摄像头）时切换 |
| 判定阈值 | 和后台共用，改完 500 ms 后写入数据库 |
| 状态行 | 实时帧率、单帧耗时（检测 + 识别）、画面里的脸数 |
| 人物图例 | 每种颜色对应一个人，后面是名字和样本数 |

**画面里的标记**

- **彩色框 + 名字 + 百分比**：已登记，且相似度达到阈值；
- **黄框 + 未知 NN%**：画面里有人，但最像的已登记人物也没达到阈值；
- **黄框 + 灰底「人脸」**：检测到脸，但特征提取失败（极少见，通常是脸太偏/出画）；
- 横幅显示稳定识别结果，例如「识别到：儿子 82%」；多人时用顿号分隔。

**投票规则**

- 页面保留最近 12 帧，每个人分别统计命中次数；
- 命中次数 ≥ 一半（且至少 2 帧）才稳定显示名字；
- 这样单帧偶然高分不会立刻报名字，减少闪烁和误报；
- 刚开摄像头的前几帧可能显示「识别中…」，属于正常现象。

**脸太小**

画面里最大的脸宽小于约 55 像素时，横幅会提示「脸太小/太远，靠近摄像头一点再试」。
这个 55 像素是识别帧（最长边缩到 960）里的宽度，不是原始摄像头分辨率。

## 6. 命令行批量导入

适合一次导入整个照片目录，比在网页里一张张选快。

```bash
# 把 photos/ 里的照片导入「儿子」；人物不存在会自动创建
npm run import -- photos 儿子

# 指定其他目录
npm run import -- ~/Pictures/儿子照片 儿子
```

规则比网页上传更严格：

- 只处理 jpg / jpeg；
- 照片里必须**恰好一张脸**（多人合影直接跳过）；
- 脸宽至少 100 像素（按原图分辨率算），检测置信度至少 0.6；
- 与这个人物已有样本相似度 ≥ 0.97 的重复照片会跳过；
- 每张照片都会打印结果：新增 / 跳过原因 / 失败原因。

导入写的是同一个 SQLite 数据库。**服务可以一直开着**：导入会递增数据库里的 revision，识别服务下一次请求时自动重新加载，不用重启。
如果遇到数据库被锁（通常是有另一个进程在长时间写），先停掉服务再导入即可。

命令结束时会给汇总：

```
导入完成：新增 71，跳过 36，失败 0；「儿子」现在共有 71 张样本。
正在运行的识别服务会自动加载新样本，不用重启。
```

注意：v2 的导入只做质量检查和去重，**不做第一版那种离群剔除**。
如果发现某个人的样本里混进了别人，去后台删掉对应的缩略图即可；大面积污染就删除人物重新导入。

## 7. 数据、备份与隐私

### 7.1 数据存在哪

```
data/
├── app.db            SQLite 数据库：人物、样本特征、阈值
├── app.db-wal        运行时的预写日志（WAL）
├── app.db-shm        运行时的共享内存文件
└── thumbs/           每张样本一张 112×112 的 JPEG 缩略图
```

- 特征：ArcFace 输出的 512 维 float32 单位向量，以 BLOB 存在 `faces.emb`；
- 缩略图：对齐后的人脸小图，约 10～15 KB 一张；
- 原始照片、原始视频、完整摄像头画面**都不保存**；
- `photos/`、`son-template.json` 是第一版留下的训练素材，迁移完成后不再参与识别。
- 桌面版的数据库和缩略图在 `~/Library/Application Support/com.fuxiangming.localface/`，见 16.3 节。

### 7.2 备份和迁移到新电脑

最稳妥的做法（先停服务，避免 WAL 里的数据没合并）：

1. 在终端按 `Ctrl+C` 停止服务；
2. 把整个 `data/` 目录复制到安全位置（U 盘、移动硬盘、你自己信任的备份盘）；
3. 新电脑上装好 Node、`npm install`，把代码、`models/` 和 `data/` 一起拷过去；
4. `npm start`，人物和样本原样恢复，不需要重新录入。

只在服务运行时复制 `app.db` 可能漏掉还在 WAL 里的最新数据，所以不建议热拷贝。

### 7.3 清空重来

```bash
# 先停止服务
mv data data-backup-$(date +%Y%m%d)
npm start
```

- 如果 `son-template.json` 还在，下次启动会再次自动迁移出「儿子」和 53 张样本；
- 如果连第一版数据也不想迁移，用 `SKIP_MIGRATE=1 npm start`，或者把 `son-template.json` 改名；
- `data-backup-*` 确认不需要后再自己删除。

### 7.4 隐私边界

- 服务只监听 `127.0.0.1`，同一局域网的其他设备访问不到；
- 浏览器和本机服务之间的数据是原始 RGBA 像素，只在这台电脑的环回网卡上传输；
- 数据库里没有完整照片，但有 112×112 的人脸缩略图，**能看出是谁**，请当作私人数据；
- 管理后台没有密码。任何能操作这台电脑的人都能打开后台、查看缩略图、删除数据；
- 不要改代码把服务绑定到 `0.0.0.0`，那会把摄像头画面和人物库暴露给局域网。

## 8. 让识别更准

1. **靠近一点**：脸在画面里越大越准。太远时先看横幅是不是提示「脸太小」。
2. **正面光**：让光从人脸正面来，别背对窗户；晚上开主灯。
3. **正对镜头**：侧脸、低头、手挡脸、口罩都会明显掉分。
4. **多补样本**：同一个人换几个角度、表情、光线，各录几张；比只调阈值有效。
5. **阈值**：
   - 经常把别人认成家人 → 调到 0.50～0.55，并检查样本里有没有混进别人；
   - 家人经常认不出 → 调到 0.40～0.42，并补 10～20 张新照片；
6. **定期更新**：小孩每半年到一年补一次照片；发型、眼镜变化大时也补。
7. **一个人一个档案**：不要把同一个人的照片分散到两个人物里，否则每个人物的样本都变少。
8. **不要在识别页开着摄像头时批量录入**：服务会串行处理推理，两边都会变慢。

## 9. 工作原理

```
浏览器（index.html）                          本机 Node 服务（127.0.0.1:5273）
┌──────────────────────────┐                 ┌─────────────────────────────────────┐
│ <video> 摄像头画面         │  原始 RGBA      │ POST /scan                          │
│ 每帧缩到最长边 960        │ ──────────────► │ 1. SCRFD 检测人脸 + 5 个关键点      │
│ <canvas> 画框、名字、分数  │                 │ 2. 5 点相似变换对齐到 112×112       │
│ 12 帧投票                 │ ◄────────────── │ 3. ArcFace w600k_r50 → 512 维向量   │
└──────────────────────────┘  框 + 人名 + 分数 │ 4. 和每个人物的样本算余弦相似度     │
                                              │ 5. 每人取最像的 5 张求平均           │
                                              │ 6. 取全场最像的人，和阈值比较         │
                                              └─────────────────────────────────────┘
```

- **检测**：SCRFD det_500m，输入固定 640×640，输出人脸框和 5 个关键点（双眼、鼻尖、嘴角）；
- **对齐**：用 5 点做最小二乘相似变换，把脸摆正、缩放到 112×112（和 ArcFace 训练时一致）；
- **特征**：ArcFace w600k_r50 输出 512 维单位向量，同一个人的向量夹角小；
- **打分**：和某个人的所有样本逐条算余弦相似度，取**最像的 5 张平均**；分数越高越像；
- **认人**：所有已登记人物里取平均分最高的一个；只有达到阈值才显示名字，否则显示「未知」；
- **投票**：页面保留最近 12 帧的命中集合，每个人单独统计，稳定后才在横幅显示名字。

**录入流程**：检测人脸 → 检查「只有一张主角脸、脸够大、够清晰」→ 和已有样本去重 → 提特征 → 生成 112×112 缩略图 → 写入 SQLite。

为什么不用纯浏览器推理：同样模型在浏览器里只有约 2.4 fps，放进本机 Node 服务后约 9 fps。
网页只负责采集和显示，所以「打开浏览器就能用」的体验不变。

## 10. 实测效果与局限

以下数字来自第一版 53 张「儿子」模板的离线测试，v2 迁移的是同一批特征：

| 测试集 | 样本 | 结果（阈值 0.45） |
|---|---|---|
| 模板内照片留一比对 | 53 张儿子照片，每次拿掉自己再比 | 中位 **0.70**，最低 **0.58**，**100%** 过阈值 |
| 模拟摄像头画质 | 相册照片压成：脸 80～220 像素 + 运动模糊 + JPEG q35～q70 | 最低 **0.48**，**100%** 过阈值 |
| 陌生人照片 | 7 张（不同年龄、性别、肤色） | 最高 **0.36**，0 张过 0.45 |
| 别的孩子画面 | 5 张男同学 + 3 张女生课堂帧 | 最高 **0.34**，0 张过 0.45 |
| 未被收录的照片 | 54 张（多人合影、脸太小、糊），其中 49 张能检出人脸 | 只有 49%～68% 过阈值（本来就是难样本） |

v2 额外验证：

- 迁移后的生产库用模板内照片调用 `/scan`，识别为「儿子」，相似度 **0.77**；
- 管理后台上传照片、重复样本去重、视频抽帧、阈值同步、人物新增/改名均已跑通；
- 用模板照片模拟摄像头视频流，识别页能稳定显示「儿子」，画框、多帧投票、横幅链路正常；
- 命令行导入 107 张照片：新增 71、跳过 36、失败 0，运行中的服务自动加载。
- 摄像头录入和文件夹批量上传的界面逻辑已实现，但开发环境拿不到真实摄像头，需要在你的浏览器里实际操作确认。

性能：

- 单张脸单帧约 **110～160 ms**（检测约 40～90 ms + 特征约 60～70 ms），界面约 **9 fps**；
- 同一帧里每多一张脸，就多一次特征提取；8 张脸会明显变慢；
- 第一版实测服务常驻内存约 380 MB（不含系统缓存），第二版数据量相近。

**必须说明的局限**

- 这套准确率数字来自照片和「模拟摄像头画质」。开发环境里的内置浏览器拿不到真实摄像头，**没有在真实摄像头下统计过准确率**，第一次请你自己在 Chrome 里实测。
- 测试视频 `test/son.mp4` 里有多个同龄小孩，**无法确认哪个是儿子**，所以没有拿它当准确率依据。
- 远距离（脸小于约 60 像素）、强运动模糊、逆光、口罩、侧脸，都会认不出或分数偏低。
- 双胞胎、长相极像的兄弟会混淆；全家人脸型接近时，陌生人被认成家人的概率也会升高。
- 没有活体检测：照片、平板屏幕里的脸也可能被认出来，不能用于安全场景。
- 多人物时每个脸只取「最像的已登记人物」。如果画面里两个人长得很像，可能都显示同一个名字。
- 儿童长相变化快，模板建议每半年到一年更新。
- v2 的批量导入不做离群剔除，需要人工删除明显录错的样本。

## 12. 常见问题

**Q：点「开启摄像头」提示打不开 / 权限错误**

1. 桌面版（LocalFace.app）：第一次点「开启摄像头」时，macOS 会弹出「“LocalFace”想访问相机」，点「允许」；
2. 如果之前误点过「不允许」：页面里会直接弹出说明，点「打开系统设置」，在 **隐私与安全性 → 摄像头** 里把 **LocalFace** 打开，再回来点「重试」；
3. 浏览器版：确认地址栏是 `http://localhost:5273`（`127.0.0.1:5273` 也可以），不要用 `file://` 打开；
4. 浏览器版：点地址栏左边的锁形/摄像头图标，把「摄像头」设为允许，然后刷新；
5. 浏览器版：macOS 系统设置 → 隐私与安全 → 摄像头，确认 Chrome / Edge 被允许；
6. 关掉正在占用摄像头的软件（Zoom、腾讯会议、微信视频、Photo Booth）；
7. 识别页和后台不要同时开摄像头；先在一个页面点「停止」/「关闭」；
8. 有多个摄像头时，在下拉框里换一个再试。

**Q：`npm start` 报端口被占用（EADDRINUSE）**

```bash
lsof -ti:5273 | xargs kill
# 或换端口
PORT=5274 npm start
```

换端口后页面地址也要用新端口。服务只会打印「端口已被占用」并退出，不会自动换端口。

**Q：启动报 `Cannot find package 'onnxruntime-node'`**

没装依赖。回到项目目录执行 `npm install`。

**Q：启动时报模型下载失败 / 检测不到人脸模型**

模型不随 git 提交，靠安装/启动时自动下载。下载失败一般是网络问题，重试即可：

```bash
npm run setup
```

脚本会先试 hf-mirror.com 镜像（国内快），失败自动换 huggingface.co；也可以挂代理后重跑。下载成功后再 `npm start`。
如果你是**从第一版升级**、`models/` 里已有模型文件，只有大小不符时才会重新下载（旧检测模型与现行版本差几 KB，会自动换成校验过的版本）。

**Q：启动报 `Cannot find module 'node:sqlite'` 或 `ERR_UNKNOWN_BUILTIN_MODULE`**

Node 版本太低。执行 `node -v`，需要 **22.13 或更高**；推荐直接用 Node 24 LTS。
升级 Node 后重新 `npm install`（`onnxruntime-node` 需要匹配 Node ABI）。

**Q：启动时提示 SQLite 是实验性功能**

Node 22/24 的 `node:sqlite` 仍标记为实验性，但功能可用。`npm start` 已经屏蔽了这条警告；
直接运行 `node server.mjs` 会看到它，不影响使用。

**Q：识别页显示「还没有登记任何人物」**

数据库是空的。打开 http://localhost:5273/admin 新增人物并录入照片。
如果你本来有第一版数据，检查 `son-template.json` 是否还在、数据库是否已经有人物（迁移只在数据库为空时执行）。

**Q：迁移后人物叫「儿子」，想改成真名**

后台点人物 → 「编辑」改名，样本不会丢。

**Q：迁移后缩略图一直是「旧样本」/「无缩略图」**

后台会在启动后从 `photos/` 里找原图重新生成缩略图，53 张大约需要十几秒。
如果原照片已经删了、改名了，缩略图就生成不了，但**特征还在，识别不受影响**，只是后台看不到小图。

**Q：上传照片被跳过**

日志会写原因，常见的有：

- **画面里有多张差不多大的人脸**：换单人人脸照片，或把别人裁掉；
- **脸太小（至少 90px）**：换分辨率更高、脸更大的照片；
- **人脸不够清晰**：太糊、太暗、严重侧脸；
- **与已有样本几乎相同**：这张已经录过了，不用重复加。

命令行导入更严格：必须恰好一张脸，脸宽至少 100px。

**Q：视频抽帧打不开 / 提示无法解码**

浏览器对视频编码支持有限。优先用 H.264 编码的 MP4；HEVC/H.265、部分 MOV、AVI 可能不行。
可以先用 QuickTime / 剪映 / ffmpeg 转成 H.264 MP4 再试。

**Q：视频抽帧很慢，或者某些帧被跳过**

逐帧跳转解码本身就要时间，12 帧十几秒是正常的。
画面里没人、脸太小、多人同框的帧会被单独跳过，不影响其他帧；这是质量保护，不是故障。

**Q：家人站在镜头前一直显示「未知」**

1. 走近一点，让脸更大；
2. 开灯、避免背光；
3. 把阈值降到 0.40 试试；
4. 去后台看看这个人的样本是不是太少、太糊、角度太单一；
5. 用摄像头「连拍 8 张」补几个角度。

**Q：认错人了**

1. 把阈值调高到 0.50～0.55；
2. 检查被认错的那个人的样本里有没有混进别人，删掉可疑缩略图；
3. 如果两个人长得像，尽量给每个人多补不同角度的样本，不要只靠一张正脸；
4. 记住这个工具没有活体检测，不能用于安全场景。

**Q：识别页状态行显示「识别服务出错」**

看终端里 `npm start` 的报错。常见原因是服务被关掉了、端口换了、或页面还开着旧地址；刷新页面或重启服务即可。

**Q：模型文件丢了 / 换电脑只拷了代码**

把这两个文件放回 `models/`：

- `arcface_r50.onnx`（512 维特征，必须叫这个名）：
  `https://hf-mirror.com/deepghs/insightface/resolve/main/buffalo_l/w600k_r50.onnx`（约 166 MB）
- `scrfd_500m.onnx`（人脸检测，固定 640×640 输入）：
  最省事的办法是用 `pip install insightface` 加载一次 `buffalo_s` 模型包，再从
  `~/.insightface/models/buffalo_s/det_500m.onnx` 拷贝过来并重命名。
  官方原始模型是动态输入，也可以直接用；如果换成其他固定尺寸的检测模型，把 `server.mjs` 里的 `DET_SIZE` 改成同样的边长。

**Q：自己换了模型，报 `Got invalid dimensions for input ... Expected: 640`**

`server.mjs` 里的 `DET_SIZE` 必须和检测模型的固定输入尺寸一致（现在是 640）。

**Q：数据库能不能用 Navicat / DBeaver 打开**

可以，它是一个标准 SQLite 文件 `data/app.db`。但服务运行时不要用其他工具长时间锁表写入；
查看可以，改数据建议通过后台，避免内存索引和数据库不一致（服务靠 revision 自动刷新，直接改库不会递增 revision）。

**Q：能不能多台电脑共用一个数据库**

不建议。这是单机工具，数据库和缩略图都在本机；把 `data/` 放到网盘/共享盘会导致锁和一致性问题。

## 13. 技术参数与接口

| 项目 | 值 |
|---|---|
| 检测模型 | SCRFD det_500m，输入 640×640（RGB、letterbox 灰边 114） |
| 识别模型 | ArcFace w600k_r50，输入 112×112，输出 512 维单位向量 |
| 对齐模板 | ArcFace 标准 5 点 `arcface_src` |
| 打分 | 余弦相似度，每个人取 top-5 平均 |
| 认人 | 所有人物中取最高分；≥ 阈值才算认出 |
| 默认阈值 | 0.45（页面可调 0.30～0.65，接口允许 0.20～0.80） |
| 录入质量门槛 | 脸宽 ≥ 90 px、检测分 ≥ 0.6、去重相似度 < 0.97 |
| 识别帧 | 最长边 960，原始 RGBA，单帧上限 12 MB |
| 投票 | 最近 12 帧，每人命中 ≥ 一半且至少 2 帧 |
| 数据库 | SQLite（`node:sqlite`，WAL 模式），`data/app.db` |
| 缩略图 | 112×112 JPEG，质量 82，`data/thumbs/<uuid>.jpg` |
| 运行时 | Node.js 22.13+ + onnxruntime-node（^1.19.2，当前安装 1.30）CPU |
| 端口 | 5273，仅绑定 127.0.0.1 |

**HTTP 接口**（供调试/二次开发；没有鉴权，只适合本机）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 人物列表、样本数、阈值、模型信息 |

| PUT/PATCH | `/api/settings` | 改阈值 `{threshold}` |
| GET | `/thumbs/:uuid.jpg` | 样本缩略图 |

## 14. 从第一版升级

第一版是「单个人物 + JSON 模板」：`son-template.json` 里 53 条特征，页面只有「是儿子 / 不像」。
第二版改成「SQLite 多人物库 + 管理后台」，升级是自动的：

1. 保留第一版的 `son-template.json` 和 `photos/`；
2. 用第二版代码覆盖项目，执行 `npm install`（依赖没变）；
3. `npm start`：
   - 如果 `data/app.db` 不存在或里面没有人物，会自动创建人物「儿子」并导入 53 条特征；
   - 如果原照片还在，后台会为这些样本生成缩略图；
4. 打开 http://localhost:5273 ，识别逻辑和阈值（0.45）与第一版一致；
5. 打开 http://localhost:5273/admin ，可以改名、补照片、加其他家人。

升级后：

- 第一版的 `npm run build-template` 命令已删除，模板重建改为「后台录入 / `npm run import`」；
- 第一版的 `son-template.json` 只在迁移时读取一次，之后不再使用；
- 第一版页面上的「把当前画面加入模板」按钮已移到后台的「摄像头录入」；
- 第一版保存的是纯特征 + 文件名，第二版额外保存 112×112 缩略图，便于检查样本质量。

如果你不想迁移第一版数据：启动时加 `SKIP_MIGRATE=1`，然后在后台从零建人物。

## 16. 桌面应用（Tauri 壳）

除了浏览器形态，项目还能打包成双击即用的 macOS 应用（`.app` / `.dmg`）。
Rust 写的 Tauri 2 壳只负责进程生命周期和窗口，识别、数据库、管理 API 仍然是同一份 Node 代码。

### 16.1 构建与运行

需要：macOS + Xcode Command Line Tools（`xcode-select --install`）+ Rust（`rustup`）。
仓库里的 `src-tauri/.cargo/config.toml` 配了 [rsproxy](https://rsproxy.cn) 镜像加速 crates 下载；在海外网络可以删掉这个文件，改用官方源。

**不想自己装环境？** 仓库配了 GitHub Actions（`.github/workflows/build.yml`）：每次 push 到 main 会自动在云端打包 Apple Silicon 版 `.app` / `.dmg`，在仓库的 [Actions](https://github.com/fuxm0818/localface/actions) 页面点进最新一次运行，Artifacts 里下载即可；打 `v*` 标签（`git tag v1.0.2 && git push --tags`）还会自动发布到 Releases。云端产物使用 ad-hoc 签名（没有 Apple 付费开发者签名），首次打开会被 Gatekeeper 拦一次，按下面的步骤放行即可。

### 从 Releases 下载安装

1. 下载 `LocalFace_<版本>_aarch64.dmg`（或 `.app.zip`），把 `LocalFace.app` 拖进「应用程序」文件夹；
2. 首次打开不要双击：在 Finder 里**右键 →「打开」**，弹窗里再点一次「打开」。如果只看到「移到废纸篓 / 完成」，去 **系统设置 → 隐私与安全性**，在底部点「仍要打开」；
3. 如果仍提示「“LocalFace”已损坏，无法打开」：说明拿到的是早期未签名的包，终端执行

   ```bash
   xattr -dr com.apple.quarantine /Applications/LocalFace.app
   open /Applications/LocalFace.app
   ```

这是 macOS 对非 App Store、非付费开发者账号应用的正常拦截，放行一次后不再提示；应用完全在本机运行，不会上传数据。

```bash
npm install
npm run desktop:build     # 首次编译 Rust，约 3～10 分钟
```

产物：

```
src-tauri/target/release/bundle/macos/LocalFace.app              ~371 MB
src-tauri/target/release/bundle/dmg/LocalFace_1.0.2_aarch64.dmg  ~218 MB
```

双击 `.app` 即可使用，不需要终端，也不需要在目标机器上安装 Node。

开发调试：

```bash
npm run desktop:dev
```

会先同步页面、组装 sidecar，再以 debug 模式启动应用；改 Rust 会自动重建。
注意：`desktop:dev` 运行的是裸二进制，摄像头会被 macOS 拒绝（见 16.4）。

### 16.2 启动与退出发生了什么

1. 壳先显示启动页 `desktop/splash.html`；
2. 选一个空闲端口、生成一次性关停令牌，启动 `server.mjs`：开发态用系统 `node`，发布版用打进包里的 `localface-server`（Node 运行时）；
3. 每 250 ms 轮询 `http://127.0.0.1:<端口>/api/state`，就绪后窗口跳到识别页；
4. 关闭窗口 / Cmd+Q / SIGTERM：壳先 `POST /api/shutdown`（带令牌）让服务优雅退出，3 秒没退再杀整个进程组；
5. 下次启动先读 `logs/backend.pid`，清理上次异常退出留下的服务进程；重复双击只会聚焦已有窗口（单实例保护）。

窗口里的页面和 API 同源，动态端口由壳注入，所以页面代码和浏览器形态完全共用。
启动失败时，启动页会显示原因，详细堆栈在 `logs/server.log`。

### 16.3 数据放在哪

桌面版使用独立的数据目录，和仓库里的 `data/` 互不影响：

```
~/Library/Application Support/com.fuxiangming.localface/
├── app.db / app.db-wal / app.db-shm
├── thumbs/
└── logs/
    ├── server.log       服务日志
    └── backend.pid      运行时进程号，正常退出后自动删除
```

把浏览器版的数据迁到桌面版：完全退出应用后，把 `data/app.db*` 和 `data/thumbs/` 复制进上面的目录。
反过来（桌面版 → 浏览器版）同理。

从旧版（包标识 `com.fuxiangming.familyface`）升级时，先完全退出旧版，再迁移数据目录：

```bash
mv ~/Library/Application\ Support/com.fuxiangming.familyface \
   ~/Library/Application\ Support/com.fuxiangming.localface
```

桌面版**不会**自动导入第一版的 `son-template.json` 或 `photos/`：全新安装的人物库是空的，
人物和照片一律由使用者在管理后台自己创建、自己录入。

要回到「全新安装」状态（人物库清空）：

```bash
# 先完全退出应用
mv ~/Library/Application\ Support/com.fuxiangming.localface \
   ~/Library/Application\ Support/com.fuxiangming.localface.backup-$(date +%Y%m%d)
```

下次打开会自动新建空库；确认备份不需要后再自己删除。

### 16.4 摄像头权限（重要）

- 第一次在桌面版点「开启摄像头」，macOS 会弹出摄像头授权，选「允许」即可。
- 如果误点拒绝：系统设置 → 隐私与安全性 → 摄像头 → 打开「LocalFace」，然后重新打开应用。
- **`npm run desktop:dev` 的裸二进制没有应用包身份，`getUserMedia` 会直接返回 `NotAllowedError`**，这是 macOS 的权限机制，不是代码问题。相机功能必须在打包后的 `.app` 里验证（本项目已实测通过，设备名 `FaceTime高清相机`）。

### 16.5 分发与已知限制

- 目前只验证了 **macOS Apple 芯片**。sidecar 命名和构建脚本支持三平台，但 Windows / Linux 没有实机验证。
- **安装包不含任何照片、视频、数据库或 v1 模板**；`npm run desktop:build` 最后会执行 `scripts/verify-bundle.mjs`，
  一旦在 `.app` 里发现这类文件就直接判定打包失败。本机使用产生的数据只存在 16.3 的 Application Support 目录里，不随包分发。
- 当前是 **ad-hoc 签名**，适合自己电脑或信得过的设备。要公开分发需要 Apple Developer ID 签名 + 公证，否则 Gatekeeper 会拦截；临时绕过是右键应用 → 打开。
- 发布版不会自动迁移第一版的 `son-template.json`（安装包里不带个人照片），需要旧数据时按 16.3 复制。
- 安装包体积主要来自模型（169 MB）、Node 运行时（112 MB）和 onnxruntime（85 MB），壳本身只有几 MB。
- `desktop-dist/`、`src-tauri/target|binaries|sidecar|resources` 都是构建产物，已加入 `.gitignore`。
